# Deploying Jalan-Jalan AI (Session 11)

Production architecture — each service has one responsibility:

```
Browser → Vercel (Next.js) → Render / FastAPI Cloud (FastAPI) → Neon (PostgreSQL)
                                          ↘ Amazon Bedrock (Nova Lite + Knowledge Base)
```

Deploy in this order: **database → backend → frontend**, then come back to the
backend to allow the frontend URL in CORS.

---

## 1. Database — Neon

1. Sign up at [neon.tech](https://neon.tech) → **New project** → choose a region close to the backend
   (e.g. AWS Asia Pacific — Singapore/Sydney).
2. Copy the **connection string** from the dashboard. It looks like
   `postgresql://user:password@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
3. Use it as `DATABASE_URL` for the backend. Tables are created automatically on startup.

## 2. Backend — Render (or FastAPI Cloud)

### Option A — Render (Blueprint)
1. Push the latest code to GitHub.
2. Render dashboard → **New → Blueprint** → pick the `kelana-ai` repo. Render reads `render.yaml`
   (root directory `backend`, build `pip install -r requirements.txt`,
   start `uvicorn main:app --host 0.0.0.0 --port $PORT`).
3. Fill in the secret environment variables:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | Neon connection string |
| `AWS_BEARER_TOKEN_BEDROCK` | Amazon Bedrock API key |
| `AWS_REGION` | `ap-southeast-2` (region where the key/model are enabled) |
| `MODEL_ID` | `amazon.nova-lite-v1:0` |
| `KNOWLEDGE_BASE_ID` | Bedrock Knowledge Base ID (leave empty to use the local `knowledge/` folder) |
| `JWT_SECRET_KEY` | auto-generated by Render (or any long random string) |
| `CORS_ORIGINS` | your Vercel URL, e.g. `https://jalan-jalan-ai.vercel.app` |
| `CORS_ORIGIN_REGEX` | optional, e.g. `^https://jalan-jalan-ai.*\.vercel\.app$` for preview deployments |

4. Deploy, then verify: `https://<your-api>.onrender.com/health` → `{"status":"OK"}` and `/docs` loads.

> Render free tier sleeps after 15 minutes idle — the first request afterwards takes ~30 s.

### Option C — Vercel (free, no credit card)
The backend can run as a Vercel Python function (`backend/vercel.json`).
1. Vercel → **Add New → Project** → import the repo.
2. **Project name:** `jalan-jalan-ai-api` · **Root Directory:** `backend` · Framework preset: **Other**.
3. Environment variables: `DATABASE_URL` (Neon), `JWT_SECRET_KEY` (long random string),
   `AI_MOCK_MODE=true` (until Bedrock works), `CORS_ORIGINS` (frontend URL, add it after step 3 below).
4. Deploy, then open `https://<backend>.vercel.app/health` → `{"status":"OK"}`.

### Option B — FastAPI Cloud
```bash
cd backend
pip install "fastapi[standard]"
fastapi login
fastapi deploy
```
Then set the same environment variables in the FastAPI Cloud dashboard and redeploy.

> The local RAG fallback reads `../knowledge`. If your platform only uploads the `backend/`
> folder, copy the documents into `backend/knowledge/` (it is checked first) or set `KNOWLEDGE_DIR`.

## 3. Frontend — Vercel

1. [vercel.com](https://vercel.com) → **Add New → Project** → import the `kelana-ai` repo.
2. **Root Directory:** `frontend` (framework auto-detected as Next.js).
3. Environment variable: `NEXT_PUBLIC_API_URL` = your backend URL (no trailing slash),
   e.g. `https://jalan-jalan-ai-api.onrender.com`.
4. Deploy. Every push to `main` redeploys automatically.
5. Copy the Vercel URL into the backend's `CORS_ORIGINS` and redeploy the backend.

## 4. Amazon Bedrock Knowledge Base (optional, Session 9)

1. Create an S3 bucket (e.g. `jalan-jalan-travel-docs`) and upload the documents:
   ```bash
   aws s3 sync backend/knowledge/ s3://jalan-jalan-travel-docs/ --exclude "README.md"
   ```
2. Bedrock console → **Knowledge Bases → Create** (`jalan-jalan-travel-kb`), data source = the S3 bucket,
   pick an embedding model, then **Sync**.
3. Set `KNOWLEDGE_BASE_ID` on the backend. If the generation model needs an inference profile in
   your region, set `KB_MODEL_ARN` to that profile ARN.

## 5. Deployment checklist

- [ ] Backend works — `/health` returns 200, Swagger `/docs` loads
- [ ] Frontend works — Vercel page loads with no console errors
- [ ] Database connected — a new trip appears in the Neon SQL editor (`SELECT * FROM trips;`)
- [ ] Authentication works — register, login, logout
- [ ] AI responses generated — itinerary appears for a sample trip
- [ ] Assistant answers with sources; chat remembers follow-up questions
- [ ] Environment variables secured — no secrets in Git (`.env` is gitignored)
- [ ] HTTPS enabled (default on Vercel, Render and Neon)

## Common issues

| Symptom | Fix |
| --- | --- |
| Browser shows a **CORS** error | Add the exact Vercel URL to `CORS_ORIGINS` (no trailing slash) and redeploy |
| Frontend calls `localhost:8000` in production | Set `NEXT_PUBLIC_API_URL` on Vercel and **redeploy** (it is baked in at build time) |
| `502 Amazon Bedrock error (AccessDeniedException)` | API key expired/invalid or wrong `AWS_REGION` — create a new key and update the env var |
| `could not connect to server` on startup | Check the Neon `DATABASE_URL` (must include `sslmode=require`) |
| 500 on startup about a missing variable | Re-check the platform's environment variable dashboard |
